# Framing Excellence

Mission framing grounded in the Charte d'Excellence — no engagement starts without a problem stated and an appetite fixed.

## Core rules

**No problem statement, no code.** Refuse to write implementation code while the problem statement, the appetite (time/money budget), and the non-goals are unknown. Ask for them, or draft a one-page pitch for the user to validate with their client.

**Appetite before scope.** The appetite decides what the problem is worth, and it trims the scope. When scope and appetite conflict, cut scope — never silently extend appetite.

**Name the rabbit holes.** Migrations, edge cases, external dependencies: the zones known to absorb weeks. Surface them in the plan before entering, and encircle them.

**Write the non-goals.** What will NOT be done in this perimeter. The client signs the whole pitch before the first framing commit.

**Deliverable-sized chunks.** Every chunk ends with something visible. No chunk ends in invisible progress.

## The one-page pitch

| Section | Content |
|---|---|
| Problem | What the client lives today, what it costs them (time, money, lost customers) |
| Appetite | Time budget, money budget, decision-maker |
| Sketch | The shape of the solution — clear enough to discuss, too rough to be a spec |
| Rabbit holes | The known traps, encircled before entering |
| Non-goals | What is explicitly out of this perimeter |
| Chunks | Deliverable-sized lots, each ending with something visible |

## Deviation

Missions under 5 days: the pitch is three lines in an email. But it exists, and it is written.
